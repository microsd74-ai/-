## Назначение и архитектура

UOP WORK — общий монитор нескольких одинаковых промышленных 3D-принтеров FHZL по локальной сети. У каждого принтера свой управляющий компьютер с FHZLPrinterManager и нашим агентом. На отдельном компьютере оператора — общий монитор, Windows 10 Pro x64.

Агент слушает TCP-порт на компьютере принтера. В агенте IP монитора не нужен. В мониторе администратор добавляет название принтера, IPv4 управляющего компьютера и порт, обычно 5055; монитор сам подключается.

Проект начинался на Lazarus, затем перешли на C# / WPF. Бренд интерфейса изменён с FHZL на UOP WORK. Старый Lazarus-проект сохранён отдельно и пока используется для агента. Монитор совместим с агентом Lazarus версии 0.3+.

## Что готово и принято пользователем

1. Широкий полноэкранный интерфейс без системной строки заголовка и кнопок свернуть/развернуть/закрыть.
2. Три сохраняемые темы: светлая, тёмная и зелёный ретро-терминал в духе Fallout. Цвет настоящего видео в будущем не должен зависеть от темы; аварии всегда красные.
3. Слева принтеры по названиям и их состояния, в центре выбранный принтер и показания, справа полученные ошибки всех принтеров. Неисправность невыбранного принтера тоже заметна.
4. Показания: слои, прогресс, окончание, температура, влажность, время без смены слоя, файл, режим, журнал принтера. Два места под камеры пока являются честными заглушками.
5. Админка с собственным паролем при первом входе, сменой пароля, добавлением/редактированием/удалением принтеров и импортом Monitor.targets.json старого монитора.
6. Журнал событий подключений убран с главного экрана и открывается из управления. Журнал самого принтера остаётся на главном экране.
7. Окна управления и пароля без белой системной плашки; закрываются внутренними кнопками. Исправлены белый фон тёмных тем и обрезанные/тусклые нижние кнопки.
8. TCP-подключение к старым агентам, переподключение, различение отсутствия связи и ошибки чтения.
9. Независимое подтверждение полученных разных аварий. Подтверждение убирает звук, но не скрывает сообщение.
10. История появления, подтверждения и снятия последних 2000 событий сохраняется в alarm-history.json; отдельная кнопка «История аварий».
11. Повтор звука каждые 10 секунд для неподтверждённых полученных аварий всех принтеров. При новой либо повторно появившейся после достоверного снятия ошибке звук включается заново.
12. Настройки звука: выбрать событие, собственный WAV, голос Windows/сигнал, проверить, остановить проверку, сохранить.
13. Контроль неподвижного слоя 60 секунд в v0.2.0, описан ниже.

Пользователь проверил реальные принтеры: FHZL TEST передаёт слои, температуру, влажность, файл и журнал; FHZL PMMA правильно показывал настоящую аварию. Затем пользователь подтвердил работу звука/женского голоса Windows и аварийных оповещений. После выдачи v0.2.0 ответил «Все отлично». ## Контроль слоя — окончательная договорённость

Первоначальное пожелание исключать паузу отменено последующими прямыми ответами пользователя. Актуально:

- Отдельный сигнал или сообщение о переходе на паузу НЕ нужны.
- Если слой не меняется 60 секунд, включается тревога остановки, **в том числе при штатной паузе**. Пользователь явно подтвердил: «Да пусть тоже включается».
- Голосовая фраза: **«Внимание! Печать остановилась!»**.
- На 59-й секунде тревоги ещё нет, на 60-й появляется.
- Подтверждение прекращает звук этой тревоги, не убирая её текст.
- Смена слоя снимает локальную тревогу. Если потом слой снова стоит 60 секунд, создаётся новая тревога с новым подтверждением.
- Контроль отдельный для каждого принтера и не зависит от выбора принтера на экране.

Реализация LayerWatchdog использует монотонное время, а не часы Windows. Контроль начинается с первого корректного незавершённого счётчика, включая загруженное, но ещё не начатое задание. Режим MainAuto/Manual и признаки кнопок Start/Pause для разрешения таймера не используются.

Потеря связи, задержка показаний больше 5 секунд, ошибка/отсутствие счётчика, printed >= total или FinishKind=FINISHED сбрасывают контроль. Смена файла/задания тоже сбрасывает таймер. После возвращения корректных данных отсчёт начинается заново. Снятие локального предупреждения при потере данных НЕ является доказательством возобновления движения.

Локальная остановка и аппаратные ошибки FHZL имеют разные трекеры и подтверждения. Пустая аппаратная аварийная строка не снимает локальную остановку. Если одновременно есть неподтверждённые аппаратные ошибки и остановки, соответствующие голосовые фразы чередуются с интервалом 10 секунд.

## Голос и звук

Два события:

- Ошибка принтера: **«Внимание! Ошибка в работе принтера!»**.
- Остановка слоя: **«Внимание! Печать остановилась!»**.

Приоритет источников для каждого события: выбранный WAV → установленный русский женский SAPI-голос Windows → встроенный трёхнотный сигнал. Голос и сигнал одновременно сейчас не звучат.

Пользователь хочет приятную мягкую женскую запись. Готовая профессиональная запись пока НЕ создана. В использовавшейся среде не было инструмента естественного синтеза речи; не утверждать, что WAV с нужным голосом уже есть. Windows-голос на компьютере пользователя работает и был принят. В будущем запись можно выбрать без переделки программы.

Управление → Звуковые оповещения → выбрать событие «Ошибка принтера» или «Печать остановилась (60 секунд)» → Проверить звук. Кнопка «Голос Windows / сигнал» только выбирает режим, воспроизведение запускает «Проверить звук». WAV ограничен 20 МБ; выбранный файл должен оставаться по указанному пути. Рекомендуются короткие записи фраз.

В демо автоматический звук отключён, ручная проверка доступна. В рабочем режиме автоматический звук включён. После перезапуска программы полученные активные ошибки требуют нового подтверждения.

## Достоверность ошибок и обновление агента

На TEST без аварии старый агент давал пустой alarm без признака успеха чтения, поэтому монитор показывал «Состояние ошибок неизвестно». Это не следует исправлять безусловной подменой пустого текста на зелёное состояние.

В сборку включена Agent-update с двумя обновлёнными скриптами прежнего агента: ReadPrinter.ps1 и ParsePrinter.ps1. Для обновления на каждом компьютере принтера:

1. Остановить только наш агент, не управляющее приложение FHZL и не печать.
2. Сохранить резервную копию двух прежних скриптов рядом с Agent.exe.
3. Заменить оба файла из Agent-update и снова запустить агент.
4. Сопоставить отображение с реальной аварийной строкой FHZL. Не создавать неисправность специально.

Скрипты только считывают UI Automation и не отправляют команды принтеру. В известной диагностике аварийная QLabel находится в mainToolBar после Exit и разделителя, перед следующим разделителем. Только успешное чтение известной пустой метки подтверждает отсутствие ошибок (extra.alarmRead=true). Отсутствие метки/панели, исключение чтения или незнакомый непустой текст не считаются отсутствием ошибок. В другой версии/локализации FHZL понадобится диагностика. Факт обновления скриптов на каждом реальном компьютере отдельно ещё не зафиксирован.

FHZL вращает сообщения 1/3, 2/3, 3/3. Счётчик убирается только из ключа сравнения, исходный текст сохраняется. Повтор того же сообщения с другим счётчиком не сбрасывает подтверждение. Разные полученные сообщения запоминаются до подтверждённой пустой строки. Отдельное достоверное снятие одной аппаратной аварии при остающихся других пока НЕ определяется. Панель поэтому содержит полученные сообщения, а не гарантированно полный текущий список. История хранит время наблюдения монитором, не неизвестное время возникновения на оборудовании.

## Настройки и выход

Рабочий профиль: %LOCALAPPDATA%\UopWork. Демо: подпапка Demo, отдельно от настоящих настроек. settings.json — принтеры, тема и пути WAV; admin.json — хеш пароля; alarm-history.json — до 2000 событий.

Пароля по умолчанию нет. При первом входе собственный пароль минимум 8 символов. PBKDF2-HMAC-SHA256 с солью и 210000 итераций, открытый пароль не сохраняется. Старый пароль Lazarus автоматически не импортируется.

Выход: Управление → пароль → «Выйти из UOP WORK». Alt+F4 открывает управление. Это пока ограничение интерфейса, а не блокировка Windows: Win/Alt+Tab не запрещены.

## Что делать дальше

Последняя просьба пользователя была сохранить этот промпт в GitHub. Следующая функциональная задача ещё не выбрана. Основные согласованные будущие этапы:

### Две камеры каждого принтера

У каждого принтера свой регистратор Hikvision и две камеры, обе смотрят на зону печати с разных сторон. Показать две камеры выбранного принтера на главном экране, увеличение по нажатию. Изображение естественных цветов независимо от темы. Пока видео отсутствует, нельзя показывать фиктивное LIVE.

Для реализации уточнить модель регистратора, RTSP и каналы. Ранее на скриншоте был адрес 192.168.1.64; не считать его общим адресом всех регистраторов. Учётные данные вводить в админке, не в переписке.

### Встроенная отправка папки задания

Пользователь присылал исходники «Отправитель стартов.zip»: две Lazarus-программы отправителя и получателя. Нужно встроить отправку папки с компьютера оператора на выбранный компьютер принтера. Кнопка «Загрузить задание» **оператору без пароля**, отдельное внутреннее окно предпочтительнее запуска сторонней программы.

В старом коде использовались TCP 45678 и F:\Start; проверить по исходникам, не считать безусловной настройкой новой реализации. Явно показывать назначение/принтер. Принимать во временное место, проверять целостность, публиковать целую папку после завершения, не портить существующие задания. Сейчас кнопка отключена.

### Рабочее место оператора Windows 10 Pro

В перспективе приложение должно заменять рабочий стол выделенного компьютера, чтобы оператор не открывал лишнее. Нужны кнопки перезагрузки и выключения с подтверждением и служебный доступ администратора.

Сейчас кнопки видны, но отключены; ограничения ОС не применялись. Полноэкранный WPF не является режимом киоска. В Windows 10 Pro нет поддерживаемого Shell Launcher как в Enterprise/IoT. Способ настройки ОС выбрать отдельно с восстановлением доступа, не блокировать пользователя преждевременно.

### Достоверные показания и дальнейшие улучшения

Можно расширять достоверные состояния «печатает/пауза/завершено», полный текущий список аварий и отдельное снятие. Не угадывать это по одному счётчику. Для 60-секундного предупреждения распознавание паузы больше не требуется по последнему решению пользователя.

Источник — FHZLPrinterManager. Известны поля Printed / Total, Start/Finished time, Layer seconds (Avg.), Total time, TIFF-путь, температура, влажность, координаты, режимы, верхняя аварийная строка, журнал. Давление каналов и цветовые PLC-индикаторы раньше надёжно не считывались. Новые методы проверять только чтением, без команд управления оборудованием.

## Проверки и выпуск следующих версий

Из каталога UopWork:

```powershell
dotnet build UopWork.sln -c Release
dotnet run --project tests/UopWork.Checks -c Release
dotnet run --project tests/UopWork.UiChecks -c Release -- artifacts/screenshots
dotnet publish src/UopWork.Desktop -c Release -r win-x64 --self-contained true -o artifacts/UopWork
```

WPF-проверки запускать на Windows. Linux позволяет кросс-сборку, но не проверку работы окон. Windows workflow дополнительно проверяет PowerShell-источник аварий. v0.2.0 прошла Core Checks и настоящие Windows UI Checks, включая виртуальные 59/60 секунд, паузу, повторную остановку, независимость подтверждений, завершение, разрыв связи и пропадание данных.

Для следующего выпуска обновить Version в Directory.Build.props, соответствующие проверки и документацию. Артефакты должны включать версию, например UOP-WORK-v0.2.1-win-x64. Готовую сборку выдавать после зелёного Actions-запуска, с понятной ссылкой и названием нужного артефакта. Обновлять версионный архив исходников и этот документ по запросу/после значимых этапов. Не включать bin/obj/artifacts, личные настройки и секреты в архив исходников.

Продолжай с актуального кода и последнего выбранного пользователем функционального этапа. Не начинай проект заново и не возвращай отменённое условие «не тревожить на паузе».
