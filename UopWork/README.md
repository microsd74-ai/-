# UOP WORK v0.3.0 — две камеры Hikvision

Новая программа для Windows 10 Pro x64, .NET 10 LTS. Это начало переноса на C#, а не завершённая реализация всех согласованных функций. Прототип Lazarus хранится отдельно в ../FHZLFleet.

## Что уже реализовано

- Широкий полноэкранный WPF-интерфейс с брендом UOP WORK.
- Светлая, тёмная и ретро-терминальная темы; выбор сохраняется.
- Список принтеров по названиям, независимые показания и журнал выбранного принтера.
- Админка с созданием пароля при первом входе, проверкой и сменой пароля, добавлением/изменением/удалением принтеров.
- Импорт Monitor.targets.json из Lazarus-версии.
- Подключение по TCP к существующим агентам 0.3+, переподключение, отдельное состояние потери связи и ошибки чтения.
- Журнал событий подключений доступен только через управление.
- Независимое подтверждение разных полученных аварий, повторный звук при новой/повторно появившейся ошибке, сохранение истории последних 2000 событий.
- Звуковые оповещения: выбранный WAV, либо установленный русский женский голос Windows, либо встроенный сигнал. Повтор каждые 10 секунд до подтверждения или достоверного снятия.
- Выбор WAV и проверка звука через «Управление → Звуковые оповещения»; история через «История аварий» на главном экране.
- Явный режим демонстрации с искусственными данными. Его настройки отделены от рабочих.

## Готовая сборка без установки C#

1. Откройте в репозитории GitHub вкладку **Actions**, процесс **UOP WORK — Windows build**.
2. Дождитесь зелёного результата конкретного запуска. Если он красный, сборка не считается готовой.
3. В **Artifacts** скачайте **UOP-WORK-v0.3.0-win-x64** и распакуйте весь ZIP.
4. Запустите **UopWork.exe** для работы с агентами. .NET SDK и Visual Studio на компьютере оператора не нужны: публикуется self-contained Windows x64.
5. Для просмотра интерфейса без принтеров запустите **Start-Demo.cmd**. Вверху обязательно видна отметка демонстрации; её значения искусственные.

Windows 10 должна быть 64-разрядной и обновлённой (рекомендуется 22H2). Программа первого этапа не имеет цифровой подписи издателя и пока не является установщиком.

Для выхода откройте **Управление**, введите/создайте пароль, затем нажмите **«Выйти из UOP WORK»**. Alt+F4 запрашивает доступ к управлению. Эта сборка **не заменяет оболочку Windows и не блокирует Win/Alt+Tab**: настройка отдельной учётной записи и ограничений ОС — самостоятельный будущий этап.

## Подключение существующих принтеров

1. Агент Lazarus версии 0.3+ должен быть запущен на управляющем компьютере, порт обычно 5055.
2. В UOP WORK нажмите **Управление** и задайте собственный пароль минимум из 8 символов.
3. Добавьте название, IPv4 компьютера принтера и порт. Либо импортируйте существующий **Monitor.targets.json** через кнопку импорта.
4. На компьютере принтера должен быть разрешён входящий TCP-порт агента в доверенной локальной сети.

Старый пароль Lazarus автоматически не импортируется: новая программа создаёт собственный пароль. Файлы Lazarus не перезаписываются.

Для подтверждения пустой аварийной строки обновите два скрипта агента из **Agent-update** готовой сборки. Инструкция: **docs/agent-update.md**. Старый агент продолжает работать; без обновления неизвестное пустое чтение остаётся неизвестным.

Звуковой режим: автоматический звук включён в рабочем режиме для неподтверждённых полученных аварий всех принтеров, включая невыбранные. Подтверждение доступно без пароля и не убирает текст. В демо автоматический звук отключён; кнопку проверки можно использовать вручную. После перезапуска активные сообщения считываются заново и требуют нового подтверждения.

Настройки хранятся в **%LOCALAPPDATA%\UopWork**. Демо использует подпапку **Demo** и не меняет рабочий список/пароль. В alarm-history.json — последние 2000 событий, в settings.json — принтеры/тема/путь WAV, в admin.json — PBKDF2-HMAC-SHA256 с солью и 210000 итераций; открытого пароля нет. Это ограничение доступа к интерфейсу, а не замена прав Windows на файлы.


## Контроль слоя (добавлен в v0.2.0)

Если при непрерывно поступающих корректных показаниях незавершённого задания слой не меняется 60 секунд, появляется отдельная тревога «Печать остановилась!». Штатная пауза **тоже вызывает эту тревогу** — так согласовано с оператором. Режим MainAuto/Manual не используется как разрешение таймера. Контроль начинается с первого корректного счётчика незавершённого задания, включая загруженное, но ещё не начатое задание.

Подтверждение прекращает только звук этой тревоги; сообщение остаётся до смены слоя. Новая остановка после смены слоя требует нового подтверждения. Завершение, смена файла/задания и потеря достоверных показаний сбрасывают локальный таймер. Это не означает снятия аппаратной ошибки FHZL. После восстановления связи отсчёт начинается заново; история сохраняет событие снятия локального предупреждения, а не утверждение о возобновлении движения.

Контроль не идёт при отсутствии/ошибке чтения счётчика, потере связи или задержке данных больше 5 секунд. Также исключены счётчик printed >= total и отметка FINISHED. Часы Windows не влияют на 60-секундный отсчёт: используется монотонный таймер. Номер сборки виден в верхней строке интерфейса и VERSION.txt.

**Управление → Звуковые оповещения**: выберите событие «Ошибка принтера» или «Печать остановилась (60 секунд)». У каждого своя запись WAV; без записи используется женский голос Windows либо сигнал. Для остановки фраза: «Внимание! Печать остановилась!». Когда одновременно есть неподтверждённые ошибки и остановки, фразы чередуются с интервалом 10 секунд. Кнопка проверки воспроизводит выбранное событие.

## Камеры в v0.3.0

Выберите принтер в «Управление» → **Камеры принтера**. Введите IP регистратора, RTSP-порт (обычно 554), логин/пароль и каналы (обычно 1 и 2). Включите камеры, проверьте и сохраните. На главном экране показываются две камеры выбранного принтера; кнопка «Развернуть» увеличивает камеру, Esc возвращает назад. Пароль защищён DPAPI для текущего пользователя Windows. Видео подключается напрямую по RTSP/TCP, звук камер выключен. Отдельно устанавливать VLC не нужно.

Подробная инструкция: **docs/cameras.md**. Пользователь сообщил модель Hikvision DS-7104NF1/4P(E); реальное изображение ещё нужно проверить на его устройстве. В демо сетевые камеры автоматически не запускаются. Сохраняйте вместе все файлы архива, включая **libvlc/plugins**. Примечания о компонентах: **docs/THIRD-PARTY-NOTICES.md**.

## Что ещё не готово

- Реальные камеры требуют проверки RTSP/логина/каналов на вашем регистраторе. Применён стандартный Hikvision RTSP; совместимость с конкретным экземпляром не объявляется проверенной до просмотра на месте.
- Профессиональная запись мягким женским голосом пока не приложена; Windows-голос зависит от установленных на компьютере SAPI-голосов. Звук необходимо проверить на реальных динамиках.
- Загрузка папок и кнопки выключения/перезагрузки отключены, до реализации и проверки.
- Состояния «печатает/пауза/остановлена» не угадываются по одному счётчику. Для старого агента показывается «Показания получены»; дополнительные состояния в демо являются примерами.
- Старый агент не сообщает, успешно ли прочитана именно пустая строка ошибок. Поэтому пустой alarm без явного alarmRead=true **не превращается в зелёное «Ошибок нет»**. Последняя ошибка сохраняется до подтверждённого снятия; одно неизвестное пустое чтение её не снимает. Следующий этап нативного C#-агента добавит достоверность этого чтения.
- Панель содержит накопленные полученные ошибки, в том числе при потере свежести. Старый FHZL показывает одну аварию за раз: отдельное снятие ошибки из вращающегося списка пока не подтверждается. Все запомненные ошибки снимаются при достоверно пустой аварийной строке. История отмечает время получения монитором, а не неизвестное фактическое время неисправности.

## Исходники и сборка

Откройте **UopWork.sln** в Visual Studio с поддержкой .NET 10 и компонентами .NET Desktop Development. Или установите .NET SDK, указанный в global.json.

```powershell
dotnet build UopWork.sln -c Release
dotnet run --project tests/UopWork.Checks -c Release
dotnet run --project src/UopWork.Desktop -- --demo
dotnet publish src/UopWork.Desktop -c Release -r win-x64 --self-contained true -o artifacts/UopWork
```

Для ручных правок:

- **src/UopWork.Desktop/MainWindow.xaml** — широкая компоновка.
- **Themes/** — цвета/шрифты и общие стили.
- **Views/** — пароль и управление.
- **ViewModels.cs** — отображаемые значения и демо.
- **src/UopWork.Core/** — настройки, пароль, разбор телеметрии, сетевое подключение.

## Проверки

В текущей Linux-среде успешно выполнены кросс-сборка WPF/XAML, самодостаточная публикация win-x64 и Core Checks: настройки/импорт, русские имена, пароли, неверные данные, реальные TCP-кадры с разорванным UTF-8. Windows EXE здесь не запускался.

Windows workflow дополнительно запускает **UopWork.UiChecks**: создаёт настоящие WPF-окна, проверяет ресурсы/привязки, переключает три темы, принтеры и снимает PNG для 1920×1080/1366×768. Скриншоты — отдельный artifact **UOP-WORK-v0.3.0-interface-screenshots**. Наличие этого теста не означает его успешное выполнение: результат конкретного запуска смотрите в Actions.

**docs/target-design.png — согласованный концептуальный рендер, не скриншот этой сборки.** Дальнейшие требования и этапы — в ROADMAP.md.
