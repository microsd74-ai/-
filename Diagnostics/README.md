# Считыватель элементов окна FHZL

Эта диагностика нужна, чтобы определить, как получать показатели, предупреждения и журнал из FHZLPrinterManager. Устанавливать Lazarus для неё не нужно. Требуется Windows с Windows PowerShell 5.1 (обычно уже установлен).

## Как запустить

1. Скачайте `FHZL-diagnostics.zip` из корня репозитория и **распакуйте весь архив** в обычную папку на управляющем компьютере принтера. Не запускайте файл прямо из ZIP.
2. Откройте FHZLPrinterManager. Оставьте видимым главный экран с показателями и журналом, как на вашем скриншоте.
3. В распакованной папке дважды нажмите `Start-Diagnostic.cmd`.
4. Дождитесь результата. Обычно это занимает несколько секунд, максимальное ожидание считывателя — 90 секунд. После завершения окно останется открытым.
5. Рядом появится папка `reports`. В ней найдите архив вида **`FHZL-diagnostic-20261106-150000-abcdef.zip`** и прикрепите его в чат.

Первый запуск выполняйте обычным способом. Если окно не найдено, проверьте, что FHZL открыт в том же пользовательском сеансе Windows. Если FHZL запущен от администратора и чтение не удаётся, считывателю может понадобиться такой же уровень прав.

Для начала достаточно одного отчёта с главного экрана. При необходимости можно вручную открыть другой экран FHZL и снова запустить диагностику: каждый запуск создаёт новый архив, старые не перезаписываются. Не нужно специально вызывать аварии принтера.

## Что делает программа

- Ищет верхние окна с названием, содержащим `FHZLPrinterManager`, и обходит их доступные дочерние элементы через Windows UI Automation (Raw View).
- Читает Name, AutomationId, класс, тип, расположение и доступность элемента, поддерживаемые шаблоны UI Automation.
- Читает ValuePattern и TextPattern, если приложение их предоставляет. Это может дать значения давления, текст предупреждений и журнала.
- Не нажимает кнопки, не меняет поля, не вызывает команды принтера, не прокручивает окно и не переводит фокус. Поля, помеченные приложением как парольные, вместе с их дочерними элементами пропускаются.
- Не обращается к Интернету и ничего никуда не отправляет. Архив передаёте вы сами. Он может содержать отображаемые FHZL имена заданий, пути к файлам и сообщения журнала.

В архиве будут:

- `report.txt` — читаемый текст элементов;
- `elements.jsonl` — элементы и их связи для анализа; поля `valueTail` и `textTail` содержат последние 8192 символа через разные интерфейсы; `valueLength` — полную длину ValuePattern; `patternErrors` — подробности сбоев отдельных интерфейсов;
- `result.json` — результат, число найденных окон/элементов и сведения об ограничениях.

## Если появилась ошибка

- `complete` — обход завершён; это ещё не гарантия доступности всех показателей FHZL.
- `partial` — сохранена часть дерева: некоторые элементы недоступны или сработали ограничения. Этот архив тоже полезен, пришлите его.
- `timeout` — считыватель не завершился за 90 секунд. Остановлен только его отдельный процесс; FHZL не завершается. Сохраняется всё, что удалось прочитать, и отметка тайм-аута.
- `window_not_found` — окно FHZL не найдено. Откройте его в том же сеансе и повторите запуск; при необходимости пришлите полученный архив.
- `failed` — отправьте архив с описанием ошибки. Если ZIP не создан, пришлите текст из окна или снимок экрана.

Завершение фонового считывателя ограничено 90 секундами; упаковка отчёта занимает дополнительное время. Обход ограничен 2500 элементами, глубиной 35 и примерно 5 МБ JSON-данных; длинные тексты ограничены 8192 символами на поле. О достижении ограничений сообщается в результате. Для большого журнала сохраняются начало и конец текста, без всего содержимого между ними. Конец ValuePattern сохраняется независимо от TextPattern: это важно для Qt/FHZL, где перемещение границ TextPattern может не поддерживаться. В первой версии сохранялось только начало — в обновлённой версии это исправлено.

Если FHZL рисует часть интерфейса самостоятельно и не предоставляет её через UI Automation, этот отчёт покажет, чего не хватает. Доступность реального окна FHZL ещё нужно проверить на вашем компьютере.

## Проверки разработчика

`tests/diagnostic_smoke.ps1` проверяет оба реальных скрипта с имитацией границы Windows UI Automation: чтение Name/ValuePattern/TextPattern, связи элементов, пропуск паролей и посторонних окон, ошибку исчезнувшего элемента, ограничение числа элементов, отсутствие окна, создание ZIP и остановку зависшего считывателя. Тесты выполнялись в PowerShell 7.5.4 на Linux; Windows PowerShell 5.1 и настоящий FHZL в этой среде недоступны.

Проверка с имитацией отказа TextPattern подтверждает: `valueTail` сохраняет последнее событие, а `patternErrors` сохраняет описание отказа. Этот вариант требуется проверить на настоящем FHZL новым отчётом.

Последний настоящий отчёт подтвердил сохранение конца ValuePattern. Также установлена точная причина ошибки TextPattern: исправлены пространства имён типов TextPatternRangeEndpoint и TextUnit на System.Windows.Automation.Text. Повторный отчёт только ради проверки основного журнала больше не требуется.
