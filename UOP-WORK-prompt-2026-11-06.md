## Назначение программы

UOP WORK — монитор нескольких одинаковых промышленных 3D-принтеров FHZL по локальной сети. На управляющем компьютере каждого принтера работает FHZLPrinterManager и наш агент. На отдельном компьютере оператора работает общий монитор.

Изначально проект делали на Lazarus для Windows, затем решили перейти на C# / WPF. Название интерфейса изменено с FHZL на UOP WORK. На компьютере оператора Windows 10 Pro x64. У пользователя нет среды C#: нужны готовые самодостаточные Windows-сборки, а при необходимости помощь с ручным редактированием исходников.

Архитектура подключения: агент слушает порт на компьютере принтера; IP монитора в агенте не задаётся. В мониторе администратор добавляет название принтера, IPv4 его компьютера и порт, обычно 5055. Монитор сам подключается к агентам.

## Важные ограничения текущей версии

- Это первый этап, а не готовая реализация всех задуманных функций.
- Настоящее видео, голос, повторяющийся звуковой сигнал и загрузка папок ещё не реализованы.
- Кнопки загрузки задания, перезагрузки и выключения видны, но отключены.
- Полная история появления/снятия аварий и автоматическая тревога после 60 секунд ещё не реализованы.
- Старый агент не даёт надёжного признака, что именно пустая строка аварий прочитана успешно. Только явный alarmRead=true позволяет считать пустой alarm подтверждением «Ошибок нет». Неизвестное чтение и отсутствие связи не должны показываться как отсутствие ошибок.
- Состояния «печатает», «пауза», «завершено» нельзя угадывать только по счётчику слоёв; в демо они искусственные, для реального агента нужна проверка источников.
- Программа пока не заменяет оболочку Windows и не блокирует Win/Alt+Tab. Ограничения ОС не настраивались.
- Подтверждение сообщения сейчас работает в текущем сеансе, без звука. Панель последних ошибок пока не является полным списком достоверно текущих аварий.

## Согласованные будущие функции

### Аварии

- Не писать «Сообщение FHZL» и «Текст верхнего сообщения не получен» в качестве нормального состояния.
- Когда отсутствие ошибок достоверно подтверждено: зелёный значок и «Ошибок нет».
- При аварии: красное сообщение с красным восклицательным значком и исходным текстом.
- Циклическое звуковое предупреждение и приятный мягкий женский голос: «Внимание! Ошибка в работе принтера!».
- Рядом небольшая кнопка подтверждения: прекращает звук, но не скрывает существующую аварию.
- Новая, дополнительная или повторно появившаяся после снятия ошибка запускает звук снова.
- Звук прекращается при подтверждении либо достоверном исчезновении ошибки в управляющем приложении.
- Нужны список текущих сообщений и история появления/снятия.
- Ошибки должны быть заметны у всех принтеров, включая невыбранные, через отметки в списке и общую панель.
- Готовая женская аудиозапись пока не создана. Не утверждать, что уже есть WAV или доступный синтезатор; проверить реальные инструменты.

### Контроль остановки печати

- Обычно слой занимает около 30 секунд, задержки до 50 секунд допустимы.
- Если при достоверно активной печати слой не меняется 60 секунд, показать тревогу остановки.
- Голос: «Внимание! Печать остановилась!».
- Подтверждение и повторный сигнал по тем же правилам.
- Не считать остановкой штатную паузу, завершение, простой, отсутствие связи или ошибку чтения.
- Порог желательно настраивать в админке.

### Камеры

- У каждого принтера собственный регистратор Hikvision и две камеры.
- Обе камеры направлены на зону печати с разных сторон.
- Показывать обе на главном экране выбранного принтера, раскрывать по нажатию.
- Видео сохраняет естественные цвета в любой теме.
- Ранее показан веб-интерфейс регистратора по адресу 192.168.1.64; не считать, что этот адрес подходит всем принтерам.
- Для реализации уточнить модель регистратора, доступность RTSP и каналы. Настройки и учётные данные задаются в админке, не публикуются в чате.

Windows CI проверяет WPF, переключение тем/принтеров, подтверждение и снятие ошибки, окна управления/пароля, правильный фон и размещение нижних кнопок при 1920×1080 и 1366×768, отсутствие системной рамки у этих диалогов. Это не заменяет проверку на настоящем принтере.

Команды из каталога UopWork:

```powershell
dotnet build UopWork.sln -c Release
dotnet run --project tests/UopWork.Checks -c Release
dotnet run --project tests/UopWork.UiChecks -c Release -- artifacts/screenshots
dotnet publish src/UopWork.Desktop -c Release -r win-x64 --self-contained true -o artifacts/UopWork
```

UI-проверки запускать на Windows. Linux позволяет кросс-сборку WPF, но не проверку работы окон. Готовую Windows-сборку выдавать после успешного соответствующего Actions-запуска. Не включать bin/obj/artifacts, личные настройки и пароли в исходный архив.

## На чём остановились — следующий шаг

Пользователь подтвердил: на компьютере настоящего принтера запущены прежний агент и управляющее приложение FHZL. Мы предложили сначала проверить живые показания, затем реализовать достоверные аварии и голос, контроль 60 секунд, камеры и загрузку заданий.

Последняя инструкция пользователю:

1. Закрыть демо и запустить UopWork.exe.
2. Открыть «Управление», создать пароль.
3. Добавить название, IP компьютера принтера и порт 5055 либо фактический порт агента.
4. Нажать «Добавить», закрыть управление и выбрать принтер слева.
5. Прислать скриншот главного экрана после подключения.

Настройки агента пока не менять. Пользователь ответил, что сейчас попробует. Результат подключения ещё не получен. Не утверждать, что реальная телеметрия уже проверена. Дождаться скриншота/сообщения, сопоставить показания с FHZL и продолжить с этого места.
